# CS 230 Portfolio

This repository contains my CS 230 software design document for The Gaming Room’s Draw It or Lose It application.

## 1. Briefly summarize The Gaming Room client and their software requirements.

The Gaming Room wanted to expand their Android game, Draw It or Lose It, into a web-based application that works across devices and operating systems. The game needed to support multiple teams and players while making sure each game, team, and player had a unique ID. They also wanted to prevent duplicate names and make the game more accessible.

## 2. What did you do particularly well in developing this documentation?

I think I did well at organizing the software requirements and explaining how the different parts of the application would work together. I also compared multiple operating systems to determine which would work best for the client. This helped me recommend the best option based on the application’s needs rather than choosing the system I was most familiar with.

## 3. What about the process of working through a design document did you find helpful when developing the code?

The design document helped me understand how the application needed to be structured before I started coding. The UML diagram was especially helpful because it showed how the classes connected and what each one was responsible for. It made implementing the relationships between games, teams, and players easier to follow.

## 4. If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

I would improve the system architecture section by adding a more detailed diagram showing how the server, database, and users connect. While I explained these components in the document, having a visual representation would make it easier to understand how the application would function as a web-based system.

## 5. How did you interpret the user’s needs and implement them into your software design? Why is it important to consider the user’s needs when designing?

I started by identifying what The Gaming Room needed the application to do. Since they needed multiple games, teams, and players, I designed the classes to support those relationships while preventing duplicate names. I also considered accessibility across different devices and operating systems. Understanding the user’s needs matters because the software should solve their problems and work as expected.

## 6. How did you approach designing software? What techniques or strategies would you use in the future?

I approached the design by breaking down the client’s requirements and deciding how the different parts of the application should work together. Using object-oriented programming principles and a UML diagram helped me organize the design. In future projects, I would continue using these techniques while spending more time planning the system architecture and considering potential challenges before starting development.
